# カート・チェックアウトに進めない不具合の調査手順

「カートに入らない」「カートからチェックアウトに進めない」「数量が変えられない」といった不具合を調べるときの、私（田中）の進め方です。
原因の多くは**アプリとテーマの干渉**か、**テーマのカスタマイズ**です。**本番テーマには一切手を触れず**、複製テーマで原因を切り分けます。

---

## 0. 最初にクライアントへ確認すること

| 確認すること | 理由 |
|---|---|
| いつから起きているか。その頃に入れたアプリ、テーマの更新、コードの変更はあるか | 直前の変更が原因のことが多い |
| どの操作で起きるか（商品ページの追加／カートの数量変更／「購入手続きへ」ボタン） | 調べる場所が変わる |
| すべての商品か、特定の商品か（バリエーション、定期購入、在庫切れ） | 商品データが原因のこともある |
| PC・スマートフォン・ブラウザの種類、ログインの有無 | 環境に依存する不具合の切り分け |
| 画面の録画かスクリーンショット、エラーメッセージ | 再現の手がかり |
| 作業用のスタッフアカウント（またはコラボレーターアクセス）の発行 | パスワードを共有してもらわない |

---

## 1. 再現する

1. シークレットウィンドウ（拡張機能・キャッシュの影響を除く）で、クライアントと同じ操作をする
2. 再現した手順を、番号付きで書き残す（あとで修正の確認にも使う）
3. 再現しない場合は、端末・ブラウザ・商品を変えて試し、条件を絞る

---

## 2. ブラウザの開発者ツールで見る箇所

Chrome で `F12`（Mac は `Cmd + Option + I`）。開いた状態でページを再読み込みしてから操作する。

### Console（コンソール）

- **赤いエラー**を探す。`Uncaught TypeError: Cannot read properties of null` のようなエラーで JavaScript が止まると、ボタンが反応しなくなる
- エラーの右側のファイル名を見る
  - `cdn.shopify.com/s/files/.../assets/xxx.js` → テーマのファイル
  - `cdn.shopify.com/extensions/...` や、アプリのドメイン（例：`xxx-app.com`）→ アプリのファイル
- `customElements.define` の重複（`has already been used with this registry`）は、アプリとテーマが同じ部品を二重に読み込んでいるサイン

### Network（ネットワーク）

フィルタに `cart` と入れてから操作する。

| リクエスト | いつ送られるか | 確認すること |
|---|---|---|
| `/cart/add.js`（または `/cart/add`） | 商品ページで「カートに追加」 | ステータスが 200 か。422 なら Response の `description`（在庫切れ、数量の上限など） |
| `/cart/change.js` | カートで数量変更・削除 | `line` と `quantity` が正しい行・数量か。2 回送られていないか |
| `/cart/update.js` | カートの数量の一括更新、メモ、属性 | `updates` の中身 |
| `/cart.js` | カートの中身の取得 | `items` と `item_count`。アプリが勝手に商品を追加・削除していないか |
| `/checkout` へのリダイレクト | 「購入手続きへ」 | 送られていなければ、ボタンのクリックが JavaScript で止められている |

- リクエストを右クリック →「Initiator」で、**どのファイルがそのリクエストを送ったか**がわかる。アプリの JS がカートを書き換えていれば、ここに出る
- 同じリクエストが 2 回送られている場合は、テーマとアプリの両方が同じボタンにイベントを付けていることが多い

### Elements（要素）

- 「購入手続きへ」ボタンが `disabled` になっていないか、`<form action="/cart" method="post">` の中にあるか
- `name="checkout"` のボタンがあるか（テーマのカスタマイズで消えていることがある）
- 透明な要素（アプリのポップアップやバナー）がボタンの上に重なっていないか。ボタンを右クリック →「検証」で、別の要素が選ばれたら重なっている

## 3. 本番テーマを触らずに検証する

### 複製テーマを作る

1. 「オンラインストア」→「テーマ」→ 公開中のテーマの「…」→「**複製**」
2. 複製に「調査用_日付」などの名前を付ける
3. 複製の「…」→「**プレビュー**」で、お客様に影響なく確認できる（プレビュー URL は `?preview_theme_id=...` 付き）

### アプリとテーマのどちらが原因か切り分ける

**A. アプリの埋め込み（App embeds）を一つずつ無効にする**

1. 複製テーマの「カスタマイズ」→ 左のメニューの「アプリの埋め込み」
2. 埋め込みを**一つずつ**オフにして、保存 → プレビューで再現手順を試す
3. 再現しなくなったら、直前にオフにしたアプリが原因の候補
4. 複製テーマの設定なので、本番テーマのアプリの埋め込みには影響しない

**B. アプリブロックを外す**

商品ページやカートのセクションに置かれたアプリブロックを、複製テーマ上で一つずつ削除して試す。

**C. 素のテーマと比べる**

1. 「テーマストアにアクセス」から、同じテーマ（例：Dawn）を未公開で追加する
2. 素のテーマで再現しなければ、**テーマのカスタマイズかアプリのブロック**が原因
3. 素のテーマでも再現すれば、**アプリのスクリプト**（テーマに関係なく読み込まれるもの）や商品データが原因の可能性が高い

**D. テーマのコードを差分で確認する**

```bash
# 公開中のテーマをローカルに取得して、素のテーマと比べる
shopify theme pull --theme <テーマID> --path ./live-theme
shopify theme pull --theme <素のテーマID> --path ./base-theme
git diff --no-index base-theme live-theme -- assets sections snippets layout
```

`assets/cart.js`、`product-form.js`、`cart-drawer.js`、`layout/theme.liquid` の変更を重点的に見る。

### アプリの埋め込み以外でスクリプトを入れているアプリ

古いアプリは `layout/theme.liquid` に直接 `<script>` を書き込んだり、`snippets` にファイルを残したりしている。
アンインストール済みのアプリのコードが残って、エラーを出していることもある。`theme.liquid` の `</head>` の直前と `</body>` の直前を確認する。

---

## 4. 原因が見つかったら

| 原因 | 対応 |
|---|---|
| アプリ | 設定の見直し（表示位置、カートの種類の設定など）→ だめならアプリの開発元に問い合わせ。再現手順と Console のエラーを添える |
| テーマのカスタマイズ | 複製テーマで修正し、プレビューで再現手順をすべて確認する |
| アプリとテーマの両方 | 例：アプリがカートドロワーに対応していない → テーマ設定でカートの種類を「ページ」にする、など影響の少ない回避策も提案する |
| 商品データ | バリエーション、在庫の設定、販売チャネルへの公開を修正する |

修正後の確認：再現手順に加えて、**商品ページでの追加、カートでの数量変更・削除、チェックアウト画面への遷移**を PC とスマートフォンで確認する。

---

## 5. 本番に反映する・元に戻す

### 反映

- 修正した複製テーマを、クライアントの了承を得てから「**公開**」する
- 公開前に、もとの本番テーマはそのまま残しておく（公開を切り替えるだけなので、もとのテーマは「テーマライブラリ」に残る）
- 公開は、注文の少ない時間帯にする

### 元に戻す

- 問題があれば、テーマライブラリに残っている**もとのテーマを「公開」し直す**だけで戻る（数秒で切り替わる）
- 個別のファイルを戻したいときは、コードエディタでファイルを開き、「**以前のバージョン**」から変更前の内容を選ぶ
- アプリの埋め込みを本番でオフにした場合は、同じ場所でオンに戻す

### 作業の記録

クライアントには次をまとめて渡す。

- 原因（何が、なぜ干渉していたか）
- 修正した内容（ファイル名と変更点）、または設定の変更点
- 確認した操作と環境
- 元に戻す方法
